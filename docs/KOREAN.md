# 한국어 품질 (M5)

## 용어 정리 (`tools/ko/terms.json`, 빌드 단계 4d)
ONLYOFFICE 한국어 번역을 한국 사용자가 아는 오피스 용어로 맞춘다. 영어 UI 시험은 영향 없음, 한국어는 `--lang=ko-KR`.
| 업스트림 | 변경 | 근거 |
|---|---|---|
| 코멘트 | 메모 | 한국어 오피스 일반 용어 |
| 머리말 / 꼬리말 | 머리글 / 바닥글 | 〃 |
| 문단 | 단락 | 업스트림이 단락/문단을 섞어 쓰므로 통일 |
| 포장(그림 배치) | 텍스트 줄 바꿈 | 오역 |
| 탭 "협업" | 검토 | 이 탭의 내용이 메모·변경 추적·비교 |
| 삽입 "테이블" | 표 | 〃 (피벗 테이블은 그대로) |
- 문서 편집기 삽입 탭 화면으로 확인(`docs/shots/m5-ko-insert.png`).
- 더 볼 것: "이미지"(209) 와 "그림"(144) 혼용, "하이퍼링크"/"링크", "슬라이드 쇼"/"슬라이드쇼", "미리 보기"/"미리보기". 문맥을 보고 바꿔야 해서 보류.

## 한자 재변환 비교 시험 (2026-11-17, `tests/hanja.ps1`)
같은 문서·같은 키 입력으로 **수정하지 않은 원본 설치 트리**(`external/upstream-*`)와 Daylight 빌드를 비교. 한/영 전환 후 "한글" 입력 → 스페이스로 확정 → 두 번 눌러 단어 선택 → 한자 키.
- 결과: **두 쪽 모두 후보창이 뜨지 않고 글자도 바뀌지 않음**(`docs/shots/m5-hanja-compare.png`, 위 2장 원본, 아래 2장 Daylight). 선택은 양쪽 모두 정상.
- 결론: 확정된 글자의 한자 재변환 불가는 우리 수정 때문이 아니라 **업스트림(웹 편집기 + CEF)의 한계**. 조합 중 한자 키(입력하면서 전환)는 이전 시험에서 정상.
- 대책은 M5 후반 검토: 조합 중 전환으로 안내, 또는 입력 보조(한자 사전 플러그인)는 소스 빌드 이후.
- 방법 주의: 방향키는 확장 키 플래그 없이 보내면 먹히지 않아 더블클릭으로 선택했다. 이 시험은 실제 키보드를 쓰므로 실행 중 손대지 말 것.
