- Avalonia+LOK 직접 구현을 접고 **ONLYOFFICE Desktop Editors 를 기반으로 UX/UI 를 바꿔 배포**한다.
- 목표 사용자: 가족·친지(비상업). 기능은 거의 전부 지원해야 한다.
- 한자 재변환 실패는 시험 중 사용자 개입 가능성이 있어 **결론 보류**(나중에 재시험).

## 1. 구조: "오버레이" 방식
저장소에 ONLYOFFICE 소스·바이너리를 **넣지 않고**, 패치와 자산만 둔다. 빌드 스크립트가 공식 설치 파일(버전 고정)에 오버레이를 적용해 우리 설치 폴더와 설치 프로그램을 만든다.
```
daylight-office-family/         (이 폴더. 2026-11-17 `onlyoffice-analysis` 에서 이름 변경)
  upstream.txt                  기반 버전(10.0.0.169)과 공식 설치 파일의 SHA-256
  patches/web-apps/*.patch      JS/LESS 수정 (파일 단위 diff, 패치마다 설명·시험 1개)
  patches/sdkjs/*.patch         (필요할 때만)
  overlay/                      그대로 덮어쓸 파일: 테마 JSON, 아이콘 SVG, 로케일, 로고 PNG
  tools/                        바이너리 패치(이름·로고·아이콘), 설치 폴더 조립, 설치 프로그램(Inno)
  tests/                        스모크·화면·입력기 시험(Win32 자동화)
  docs/                         이 계획, UX 사양, 라이선스 고지, 변경 이력
```
- 재현성: `tools/build` 한 번으로 "공식 설치 파일 받기 → 검증 → 풀기 → 패치 → 조립 → 설치 프로그램".
- 업스트림 소스(`web-apps`, `sdkjs`)는 패치 작성·충돌 확인용으로 **저장소 밖**(`external/`, git 제외)에 태그 고정으로 둔다(OFFICE 의 `external/` 규칙과 같음).
- AGPL: 배포 시 받는 사람에게 대응 소스를 줘야 하므로 패치 저장소(+기반 태그 링크)를 접근 가능하게 둔다.

## 4. 단계(마일스톤)와 완료 기준
**M0 기반(저장소·빌드·시험 뼈대) — 완료 2026-11-17**
- 새 저장소 생성, `upstream.txt`, 재현 가능한 조립 스크립트(사본 폴더 생성까지).
- 스모크 시험 자동화: 실행 → 문서 열기 → 창 제목·아이콘 확인 → 스크린샷 저장. (오늘 쓴 Win32 자동화 코드를 `tests/` 로 이식.)
- 완료: 한 줄 명령(`tools\build.ps1`)으로 `build/app`에 우리 폴더가 생기고 스모크(`tests\smoke.ps1`) 통과. (결과 위치는 `dist/`가 아니라 `build/app`)

**M1 정체성·고지**
- 이름(10자 이내), 로고 8종(+2배율), 창·exe·작업 표시줄 아이콘, 연결 아이콘 73개, About 고지, 원 개발자 표시 유지.

- 업데이트 확인 차단, AI·클라우드·피드백 진입점 제거, 실제 네트워크 통신 점검.
- 완료: 화면 어디에도 ONLYOFFICE 로고·이름이 제품명으로 남지 않고(고지 제외), 오프라인에서 외부 호출이 없다.

## 5. 시험 전략
- 패치 하나 = 설명 + 시험 하나(`tests/`). 패치 매니페스트(번호, 목적, 대상 파일, 시험, 위험)를 유지한다.
- 화면: 고정 창 크기에서 스크린샷 → 기준 이미지와 비교(사람이 승인한 것만 기준으로).
- 입력기: 실제 키 입력으로 한글 조합·한/영·한자(오늘 방식). **시험 중에는 앱을 직접 건드리지 않는다**(오늘 겹침 발생).
- 업그레이드: 새 업스트림 태그에 패치를 적용해 충돌 목록을 뽑는 스크립트(분기마다).
- UX 배치는 완성에 가까워지며 사용자가 직접 써 보고 조정(기존 합의 유지).
